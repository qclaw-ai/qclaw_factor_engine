# 因子值生成使用说明（给外部开发者）

本文档用于指导第三方开发者在 `qclaw_factor_engine` 仓库内，以**开发环境**方式独立生成因子值 CSV。


## 1. 你会得到什么

- **批量区间因子值（主线）**：按时间区间批量计算，输出到 `factor_values/by_universe/{UNIVERSE}/`。
- **单日因子值（日更线）**：按单个交易日 `T` 计算，输出到 `factor_values/daily/by_universe/{UNIVERSE}/{T}/`。
- 输出列统一为：`trade_date, stock_code, factor_value`。


## 2. 前置条件

- 已拉取本仓库代码并进入仓库根目录：`qclaw_factor_engine`。
- Python 环境可用（建议 `Python 3.10+`）。
- PostgreSQL 可连接，且已存在行情表 `stock_daily`。
- 因子文档可解析（`factor_docs` 中有公式定义）。


## 3. 配置文件准备

在仓库根目录准备 `config_dev.ini`（可基于 `config_sample.ini` 复制）。

> 开发环境建议始终显式传 `--config config_dev.ini`，避免误用默认配置。

### 3.1 必填：数据库

```ini
[database]
db_host = 127.0.0.1
db_port = 5432
db_user = postgres
db_password = your_password
db_name = db_factor
```

### 3.2 批量计算配置（`factor_engine`）

```ini
[factor_engine]
start_date = 2025-01-01
end_date = 2025-12-31
factor_ids =                ; 留空=跑全部，或填：FACTOR_DEMO_0001,JQ_ALPHA_001
universe = ALL              ; 也可 HS300 / ZZ500 / ...
batch_id =
skip_factor_ids =
```

### 3.3 非 ALL 域的额外配置（需要聚宽账号）

如果 `universe` 不是 `ALL`，需配置：

```ini
[jq]
user = your_jq_user
password = your_jq_password
```


## 4. 生成“批量区间因子值”（推荐主入口）

### 4.1 直接按 `config_dev.ini` 执行

```powershell
python src/factor_engine/factor_engine_runner.py --config config_dev.ini
```

### 4.2 开发环境最小联调（先跑 1~2 个因子）

```powershell
python src/factor_engine/factor_engine_runner.py `
  --config config_dev.ini `
  --start-date 2025-03-01 `
  --end-date 2025-03-31 `
  --factor-ids JQ_ALPHA_001,JQ_ALPHA_002 `
  --universe ALL
```

### 4.3 命令行覆盖时间和因子（常用）

```powershell
python src/factor_engine/factor_engine_runner.py `
  --config config_dev.ini `
  --start-date 2025-01-01 `
  --end-date 2025-03-31 `
  --factor-ids JQ_ALPHA_001,JQ_ALPHA_002 `
  --universe ALL
```

### 4.4 结果位置

- CSV 输出目录：`factor_values/by_universe/{UNIVERSE}/`
- 文件名样式：`{factor_id}_{UNIVERSE}_{publish_start_date}_{end_date}.csv`
- 同时会更新元数据表：`factor_value_files`（`artifact_type=batch_csv`）


## 5. 生成“单日因子值”（日更）

### 5.1 执行示例（开发环境）

```powershell
python src/daily_factor_values/daily_factor_values_runner.py `
  --config config_dev.ini `
  --trade-date 2025-12-31 `
  --universe ALL
```

### 5.2 指定少量因子联调

```powershell
python src/daily_factor_values/daily_factor_values_runner.py `
  --config config_dev.ini `
  --trade-date 2025-12-31 `
  --universe HS300 `
  --factor-ids JQ_ALPHA_001,JQ_ALPHA_002
```

### 5.3 结果位置

- CSV 输出目录：`factor_values/daily/by_universe/{UNIVERSE}/{trade_date}/`
- 文件名样式：`{factor_id}.csv`
- 同时会更新元数据表：`factor_value_files`（`artifact_type=daily_csv`）


## 6. 常见问题排查

### 6.1 提示“行情数据为空，无法计算”

- 检查 `stock_daily` 在对应日期区间是否有数据。
- 检查 `start_date/end_date` 或 `--trade-date` 是否超出行情覆盖范围。

### 6.2 某些因子没产出文件

- 批量线：确认 `factor_ids` 是否把该因子过滤掉了，或在 `skip_factor_ids` 中被排除。
- 日更线：默认 `scope` 可能影响因子集合；可在配置中将 `[daily].scope` 设为 `all_in_basic`。
- 长窗口因子可能因为回看窗口不够导致当日无有效值，可增大 `[daily].lookback_days`。

### 6.3 非 ALL 域报错

- 检查 `[jq] user/password` 是否配置。
- 检查 `universe` 值是否合法（如 `ALL/HS300/ZZ500`）。

### 6.4 本地开发常见误区

- 未显式传 `--config config_dev.ini`，导致读取了其他环境配置。
- 开发库里行情时间覆盖较短，但命令传了很大的时间区间。


## 7. 给外部使用者的最短操作清单（开发环境）

1. 复制 `config_sample.ini` 为 `config_dev.ini`，填好 `[database]`。
2. 填 `[factor_engine]` 的日期和 `universe`。
3. 执行批量命令：`python src/factor_engine/factor_engine_runner.py --config config_dev.ini`。
4. 到 `factor_values/by_universe/{UNIVERSE}/` 拿 CSV。
5. 若要日更，再执行 `daily_factor_values_runner.py --config config_dev.ini`。


## 8. 说明

- 因子公式来自 `factor_docs` 解析结果，核心计算代码在 `src/factor_engine/factor_engine_runner.py` 的 `compute_factor_values(...)`。
- 开发环境建议先小范围联调（短时间区间 + 少量因子），确认产物和口径后再放大范围。


## 9. 关键代码与目录定位（你最常需要看的地方）

### 9.1 因子文档放哪里

- 默认目录：`factor_docs/md/`
- 配置项位置：`config_dev.ini` 的 `[paths].factor_docs_dir`
- 说明：因子定义（`factor_id`、公式等）从这个目录下的文档解析而来。

### 9.2 因子文档由哪个文件解析

- 解析文件：`src/factor_docs/factor_docs_parser.py`
- 关键函数：`load_all_factors()`
- 返回：`FactorDefinition` 列表（后续会被 `factor_engine_runner` 过滤并逐个计算）。

### 9.3 算子是哪个文件

- 主文件：`src/factor_engine/factor_engine_runner.py`
- 算子实现示例：
  - `MA/REF`：`_ma(...)`、`_ref(...)`
  - `CORR/RANK/DELTA/TS_*`：同文件内 `_corr(...)`、`_rank(...)`、`_delta(...)`、`_ts_sum(...)` 等
- DSL 白名单文件：`src/factor_engine/factor_dsl_allowlist.py`
  - 作用：限制公式里允许出现的字段/函数名，和运行时 `locals_dict` 保持一致。

### 9.4 实际计算入口是哪个函数

- 文件：`src/factor_engine/factor_engine_runner.py`
- 主入口函数：`run_factor_engine(...)`
- 核心计算函数：`compute_factor_values(formula, price_df)`
- 后处理函数：`winsorize_and_standardize(series)`（去极值 + 标准化）

### 9.5 日更为什么也能复用同一套算子

- 文件：`src/daily_factor_values/daily_factor_values_runner.py`
- 复用内容：
  - `_load_stock_daily`
  - `compute_factor_values`
  - `winsorize_and_standardize`
- 结论：批量线和日更线使用同一套公式执行与算子逻辑，只是时间窗口与输出路径不同。
